## 1. OpenHands cannot reach the local OpenAI-compatible LLM server — `litellm.InternalServerError: OpenAIException - Connection error.`

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**     | With an OpenHands LLM profile pointed at a self-hosted OpenAI-compatible server on another device, every request fails in the UI with`litellm.InternalServerError: InternalServerError: OpenAIException - Connection error.` No agent work runs; the failure is at the transport layer, before any model call succeeds.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Date**        | 2026-08-03                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Environment** | Windows 11, project directory`C:\Users\LOQ\Desktop\Projects\Bhai-To-Bhai`. OpenHands configured via the Advanced tab with LLM Provider `OpenAI`, model `openai/<model-id>`, base URL `http://192.168.1.14:3001/v1`, and an API key (a placeholder is acceptable where the server does not authenticate).                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Diagnosis**   | **Not established.** `Connection error` from LiteLLM means the HTTP request never completed, which narrows it to reachability or address rather than model behaviour, but the specific cause was not isolated before the trial was abandoned. Untested hypotheses, in rough order of likelihood: (a) OpenHands runs in a container, so `192.168.1.14` must be reachable *from inside that container*, not merely from the Windows host; (b) the serving device's firewall blocks inbound connections on port 3001; (c) the model ID does not exactly match an `id` returned by `http://192.168.1.14:3001/v1/models`, though this would normally surface as a model error rather than a connection error; (d) the server binds to loopback only rather than `0.0.0.0`. |
| **Resolution**  | **Unresolved.** The trial was not resumed: the next step considered was to bypass the UI and drive OpenHands through its Python SDK, but the execution layer decision moved to Maestro the same day (ADR-004), so OpenHands is no longer on the path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Prevention**  | Verify endpoint reachability*from the process that will actually make the call* before configuring any tool against it — for a containerised consumer that means `curl http://<host>:<port>/v1/models` from inside the container, not from the host shell. This applies directly to the planned DeepSeek adapter, which will target an OpenAI-compatible endpoint the same way (Research topic 6).                                                                                                                                                                                                                                                                                                                                                                                 |

| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**                | The Claude Code installer (`irm https://claude.ai/install.ps1 \| iex`) reported success and installed v2.1.220 to `C:\Users\LOQ\.local\bin\claude.exe`, but invoking `claude` in PowerShell failed with `CommandNotFoundException`. The installer itself flagged the cause in its setup notes.                                                                                                                                               |
| **Date**                   | 2026-08-03                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Environment**            | Windows 11, PowerShell. Binary present and functional —`& "C:\Users\LOQ\.local\bin\claude.exe" --version` returned `2.1.220 (Claude Code)`.                                                                                                                                                                                                                                                                                                    |

## 3. `preflight.py` cannot find the Maestro binary after the repo-local install migration

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**     | `python orchestrator/preflight.py` exits 1 with `[FAIL] Maestro: binary not found on PATH: maestro`, even though Maestro is installed and functional in this repository (`./node_modules/.bin/maestro --version` → `0.5.61`). A second failure in the same run, `[FAIL] MongoDB: pymongo is not installed in this Python environment`, has a different cause.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Date**        | 2026-08-04                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Environment** | Windows 11, project root`C:\Users\LOQ\Desktop\Projects\Bhai-To-Bhai`, root `.venv` on Python 3.13.13. Full run output: Maestro FAIL, Agent config PASS (`C:\Users\LOQ\.maestro\cli-tools.json`), Agent: codex PASS (`codex-cli 0.146.0`), MongoDB FAIL, Git worktree PASS (`git version 2.52.0.windows.1`). Exit code 1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Diagnosis**   | **Established, two independent causes.** (a) `preflight.py:219` calls `check_version("Maestro", "maestro", timeout)` with a bare command name, which `_resolve_executable` resolves through `shutil.which`. ADR-007 uninstalled the global `maestro-flow` package the same day the preflight was written, so `maestro` is no longer on `PATH` by design — it lives at `node_modules/.bin/maestro` and is reachable only via `$CLAUDE_PROJECT_DIR` or a relative path. Note the asymmetry the check itself exposes: enabled *agent* binaries are resolved from `cli-tools.json` and so can be overridden with a `command` field, but the Maestro probe is hardcoded. (b) The root `.venv` contains no installed packages at all — `pymongo` is absent because nothing has ever been installed into it, and `requirements.txt` still does not exist in the working tree or in git history, as `Status.md` (2026-08-03) recorded. MongoDB itself is running and reachable on `localhost:27017`. |
| **Resolution**  | **Open.** Neither cause is fixed. The Maestro probe needs to resolve the local install — reading a configurable path that defaults to `node_modules/.bin/maestro` and falls back to `PATH`, rather than assuming `PATH`. The MongoDB failure needs `requirements.txt` written and installed, which is Build Guide Stage 0 work that has not been done.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Prevention**  | This is the Prevention note from#2 firing against its own author within hours, and the generalized lesson is sharper than that note stated: it is not enough for a binary to be *resolvable*, it must be resolvable **the way the code looks for it**. Changing where a dependency lives is a breaking change to every consumer that hardcodes its lookup strategy. Concretely for this project — every agent executable, including Maestro itself, should be resolved through one configurable code path with an explicit precedence (config entry → project-local `node_modules/.bin` → `PATH`), never through a bare name embedded in a call site. Worth applying before the Stage 4 adapter interface exists, since that is where the same lookup will be duplicated per vendor.                                                                                                                                                                                                                                    |

## 4. LangGraph/LangChain 1.x API drift blocked the tutorial graph six times

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**     | Six consecutive failures while building`yt-tutorial/research_builder.py` and its dependencies, each blocking the next: `ImportError: cannot import name 'GraphState' from 'langgraph.graph'`; the same import error again after an incorrect fix; a bare `RuntimeError` with no message from `research_builder.add_node("supervisor", research_supervisor_node)`; `ValueError: Found edge ending at unknown node *end*` from `.compile()`; a `uv pip install mermaid` resolution failure (`mermaid==0.3.2 has invalid metadata ... torch (>=1.7torchvision)`); and `ModuleNotFoundError: No module named 'Path'`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Date**        | 2026-08-04                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Environment** | `yt-tutorial/.venv` on Python 3.12.10, `langgraph` 1.2.10, `langgraph-prebuilt` 1.1.0, `langchain` 1.3.14, `langchain-core` 1.5.3. Tutorial material written against an earlier release.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Diagnosis**   | **Established.** One genuine typo, four instances of API drift, one wrong assumption. `GraphState` is not a LangGraph export — the builder is `StateGraph` (the name was transposed) and the state type is user-defined, typically subclassing `MessagesState`. The bare `RuntimeError` came from a missing `return supervisor` at the end of `make_supervisor_node`, so `add_node` received `None`; the error names neither the node nor the cause. The `*end*` edge error came from hand-writing the literal `'_end_'` in the supervisor's `Command[Literal[...]]` annotation instead of using the exported `END` constant (whose value is `"__end__"`) — LangGraph treated the string as an ordinary node name and failed only at compile time, reporting the edge rather than the string. The `mermaid` install was an unnecessary assumption: `draw_mermaid_png()` needs no PyPI package, and the package that shares the name is uninstallable regardless because its metadata declares a malformed dependency. `Path` is `pathlib.Path`. Separately, the tutorial's `create_react_agent` from `langgraph.prebuilt` was replaced with `create_agent` from `langchain.agents`. |
| **Resolution**  | **Fixed, all six.** The graph now compiles and renders `research_graph.png`. It has **not** been invoked — see #5 and #6 for what is waiting on the first run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Prevention**  | Treat tutorial material for this ecosystem as a source of architecture, not of API: take the structure, then translate every import and constructor against the installed version before running anything. Two of these six pointed at the wrong location entirely, so read the*construction site* rather than trusting the traceback when a LangGraph error is contentless or names an edge. And do not install a PyPI package to satisfy a call until confirming the call actually needs one. Recorded in fuller form as `Research.md` topic 10.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

## 5. Tutorial supervisor node will crash on first invocation — `LLMResult` subscripted as a dict, no structured-output binding

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**     | **Not yet observed.** `research_builder.py` compiles the graph and renders the PNG but never invokes it, so the supervisor body has never executed. On the first `.invoke()` or `.stream()` it will raise `TypeError: 'LLMResult' object is not subscriptable` at `yt-tutorial/state.py:27`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Date**        | 2026-08-04 (identified by reading)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Environment** | `yt-tutorial/`, Python 3.12.10, `langgraph` 1.2.10, `langchain` 1.3.14.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Diagnosis**   | **Established statically, two coupled defects.** (a) `state.py:26-27` does `response = llm_invoke(llm, messages)` then `goto = response["next"]`, but `llm_invoke` is declared `-> LLMResult` (`llm_caller.py:838`) and `LLMResult` is a plain `@dataclass` with no `__getitem__`; the model's text is at `response.content`, and success is signalled by `response.ok`, which is not checked either. (b) More fundamentally, the structured-output layer the tutorial's design depends on is **absent entirely** — there is no `Router` TypedDict declaring `next: Literal[*options]` and no `.with_structured_output(Router)` binding on the LLM. Even with (a) corrected to read `.content`, the supervisor would be parsing free-form model prose for a routing decision, and any value not matching a member name or `FINISH` would fail against the `Command[Literal[*members, END]]` annotation. Two cosmetic issues sit alongside: `make_supervisor_node` is annotated `-> str` when it returns a callable, and the system prompt is assembled from adjacent f-strings that concatenate without a space (`"between the" "following workers"`). |
| **Resolution**  | **Open.** The fix is to define the `Router` TypedDict, bind it with `.with_structured_output(Router)`, and either invoke that bound model directly or extend `llm_caller.llm_invoke` to accept a structured-output schema and return the parsed object. The latter is the more useful direction, since it keeps the FIFO gate and rate-limit handling in the path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Prevention**  | The specific trap is that a graph **compiling is not evidence that it runs** — LangGraph validates node registration and edge targets at `.compile()`, and nothing inside a node body is checked until it executes. The general lesson matters more for this project than the tutorial: when porting a module across projects (ADR-009), its return *type* is part of its contract and does not survive being assumed. Worth a smoke invocation as the definition of done for any graph, not a successful compile.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## 6. Ported `llm_caller.py` adaptive cooldown silently degrades to zero against the configured OpenAI-compatible endpoint

| Field                 | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Symptom**     | **Not yet observed, and by design will produce no error when it happens.** The adaptive inter-call cooldown in `yt-tutorial/llm_caller.py` will compute a floor of `0.0` on every call, disabling the throttle that exists to stop back-to-back calls draining the token window. The only signal is a `logger.debug` line: `could not extract rate-limit headers — cooldown base will be 0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Date**        | 2026-08-04 (identified by reading)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Environment** | `yt-tutorial/llm_caller.py` ported from `RAG-work` (ADR-009); `llm_setup.py` configures four `ChatOpenAI` clients against a custom OpenAI-compatible base URL (`CUSTOM_API_BASE`), with the original `ChatGroq` clients commented out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Diagnosis**   | **Established statically.** The cooldown floor is derived from Groq's `x-ratelimit-remaining-tokens` / `-limit-tokens` / `-reset-tokens` response headers, which `_parse_token_headers` (`llm_caller.py:699`) reads from `_captured_response_headers`. That global is populated only by `_on_groq_response`, attached by `_install_header_hook` (`:97`), which walks `llm.client._client` and returns early unless the result `isinstance(..., httpx.Client)`. For `ChatOpenAI`, `llm.client` is the OpenAI SDK's `Completions` resource and `._client` is the `OpenAI` client object, not an `httpx.Client` — so the hook silently declines to attach and the global stays `None`. Both documented fallbacks then miss as well: LangChain's `ChatOpenAI` puts `token_usage` / `model_name` / `finish_reason` in `response_metadata`, not `headers`. `_parse_token_headers` returns `(0.0, 0.0, 0.0)`, and `_compute_cooldown_base` yields `0.0`. Even if the hook did attach, a non-Groq server is unlikely to emit Groq's header names or its duration format (`_parse_groq_duration`). **Scope of the defect is narrow and should not be overstated**: the FIFO gate, retry/backoff, the global token-reset deadline, the `LLMRateLimitAbortError` threshold, and the error taxonomy all still function — the taxonomy explicitly catches both `groq.*` and `openai.*` exception classes. Only the *header-derived cooldown floor* is inert. |
| **Resolution**  | **Open, and accepted for now** — this is sandbox code (ADR-008) and the degradation is graceful. The fix is to make header extraction vendor-pluggable: attach the hook by inspecting the actual transport rather than assuming a Groq client shape, and read header names from configuration.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Prevention**  | The dangerous property here is not the bug but its **silence** — a crash would have surfaced on the first run, whereas a throttle that quietly becomes a no-op only shows up as unexplained rate limiting much later. This is a direct rehearsal of a risk ADR-006 already names: vendor-specific strings and header names belong in configuration, not in code, and a *derived* safety value that silently defaults to "no protection" should log at warning level or refuse to start, not at debug. When the budget ledger is built, an inability to read consumption must be a visible degraded state in the ledger, never an implicit zero.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
