---
title: "Knowledge Precipitation Management System"
---

Maestro’s knowledge precipitation is divided into two types: **constraints** and **accumulation**. Constraints are coding conventions, architectural decisions, quality rules—defining "what must not be done." Accumulation is operational steps, design assets, debugging experience—recording "how it was done." The former needs to be forcibly loaded, the latter needs to be retrieved on demand.

> For authoritative system design, see [Maestro Knowledge System Architecture](../docs/knowledge-system-architecture.md). This article focuses on daily operations; identity model, Run ledger, reconciliation freshness, retrieval diversity, and secure pruning are subject to the architecture document.

<details>
<summary>Artifact directory structure</summary>

```
.workflow/
├── specs/                          # Constraint layer: rule index based on category
│   ├── coding-conventions.md       # category: coding
│   ├── architecture-constraints.md # category: arch
│   ├── review-standards.md         # category: review
│   ├── debug-notes.md              # category: debug
│   ├── test-conventions.md         # category: test
│   └── learnings.md                # category: learning (lessons learned)
├── knowhow/                        # Accumulation layer: complete knowledge documents
│   ├── KNW-*.md                    # Conversation compression records
│   ├── RCP-*.md                    # Operating recipes (step-by-step guides, can be marked tool: true)
│   ├── TPL-*.md                    # Code/config templates
│   ├── REF-*.md                    # External document summaries
│   ├── DCS-*.md                    # Architecture decision records
│   ├── TIP-*.md                    # Quick tips
│   ├── AST-*.md                    # Code assets (API contracts, data models)
│   ├── BLP-*.md                    # Architecture blueprints
│   └── DOC-*.md                    # Long-form documents (general fallback)
├── domain/                         # Domain knowledge: project glossary
│   └── glossary.yaml               # Domain terms (YAML format, primary format; glossary.json for backward compatibility)
├── wiki-index.json                 # Unified index (auto-generated by WikiIndexer)
└── codebase/
    └── knowledge-graph.json        # Code knowledge graph (queried via kg CLI)
```

</details>
